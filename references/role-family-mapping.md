# 岗位族推导与检索矩阵

> 把"人"翻译成"该往哪找机会"。这是整份档案的产出出口——前面所有分析都为了这一步。

---

## 一、推导五步

### 第 1 步 · 抽能力原子

**能力原子 = 可独立验证、可被追责的具体能力。**

判据：能否用一句"他做过X、做到Y程度"来描述。做不到，说明颗粒度太粗。

| 颗粒度 | 表述 | 判定 |
|---|---|---|
| 太粗 | 沟通能力强 | ❌ 无法验证 |
| 太细 | 负责过某个具体项目 | ⚠️ 事实而非能力 |
| 合适 | 跨部门需求对齐与优先级裁决 | ✅ 可验证、可追责 |

**抽取时保留三类**：
- 硬技能（工具、方法、资质）
- 业务能力（对特定业务链路的理解）
- 通用能力（带团队、跨职能、危机处理、资源争取）

第三类常被忽略，但它恰恰是迁移半径的来源。

### 第 2 步 · 挂职能族

把能力原子挂到市场上存在的**职能族**（不是具体岗位名——岗位名每家叫法不同，职能族才稳定）。

挂载原则：

- 一个能力原子可以挂多个族，取交集最多的组合
- 优先挂"能力组合唯一"的族（组合越独特，越能解释这个人为什么值钱）
- 排除只靠单一通用能力就能进的族（那里竞争激烈，个人的差异化无法体现）

**职能族举例**（示例，实际按行业调整）：
产品与解决方案、研发与工程、数据与算法、供应链与制造、质量与可靠性、销售与商务、职能中台（人力/财务/法务）、市场与品牌、运营与交付、客户成功、项目与PMO、组织与人才发展

### 第 3 步 · 加行业约束

对每个族，判断行业经验的必要性：

| 约束类型 | 判定标准 | 影响 |
|---|---|---|
| 强约束 | 该族的核心业务链路高度依赖行业know-how（如某些专业领域） | 需叠加行业词，检索范围收窄 |
| 中约束 | 有行业捷径但可迁移 | 可标注"同行业优先" |
| 弱约束 | 通用方法论为主 | 迁移半径最宽，可投面最大 |

**这一步的判断价值最高**：一个人是"窄而深"还是"宽而可塑"，直接由这一步决定。

### 第 4 步 · 定职级区间

用三个可验证的锚点推算：

| 锚点 | 说明 |
|---|---|
| 年限 | 注意扣除重叠口径，实际年限常被高估 |
| 汇报层级 | 直接汇报对象的层级，最硬的锚 |
| 团队规模 | 带团队人数（问清是否含虚线管理） |

输出为**区间**：「该岗位族中，汇报层级 X、团队 Y 人的形态对应的职级带约为 Z 区间」。

不要输出具体职级名——不同企业命名体系不同。写「负责一条线的层级」比写「总监」更可用。

### 第 5 步 · 排优先级

排序依据三个维度，都用高/中/低描述，不打分：

| 维度 | 问什么 |
|---|---|
| 能力证据覆盖度 | 岗位族的核心要求中，有几项有 E1/E2 证据支撑？ |
| 迁移半径 | 换行业还成立吗？ |
| 当前市场确定性 | 该职能族当前的市场需求情况（需外部数据支撑） |

**三档输出**：
- **首选方向**：三项均高
- **可延伸方向**：两项高、一项需补
- **暂不建议方向**：覆盖度低——并写明缺哪项，以及补齐的可行性

## 二、检索关键词矩阵

每个候选职能族输出一组可直接使用的关键词。

**五类词各司其职**：

| 词类 | 作用 | 示例形态 |
|---|---|---|
| 职能词 | 锁定岗位类别 | 供应链计划、品类运营 |
| 场景词 | 锁定业务语境 | 硬件量产、SaaS交付、跨境履约 |
| 能力词 | 锁定能力组合 | 供应商开发、交付预测、库存周转 |
| 行业词 | 收窄或放宽行业范围 | 消费电子、储能、新能源 |
| 职级词 | 锁定层级 | 负责人、Head of、总监级 |

**矩阵输出格式**：

```
### 首选方向 A：〔职能族名〕
- 定位：〔一句话说明这个人在这个族里是什么角色〕
- 职级区间：〔层级描述 + 区间〕
- 行业要求：〔强/中/弱约束 + 说明〕
- 关键词组合：
  · 职能词：…
  · 场景词：…
  · 能力词：…
  · 行业词：…
  · 职级词：…
- 需要补的证据：〔列出待验证项〕
- 检索备注：〔与另一个族重叠的词，注意区分〕
```

**矩阵的使用价值**：顾问拿到这张表，可以直接贴进任何一个招聘平台的搜索框，或直接写进客户的需求单，不需要二次翻译。这是本技能"可直接使用"这一原则的具体体现。

## 三、推荐材料的结构

**原则：推荐材料不是简历的复读，是替客户完成预筛。**

客户（用人主管）关心三件事：**这个人能解决什么问题、凭什么信、有什么风险**。推荐材料应该按这个顺序回答。

### 结构模板

```
〔人选代号〕推荐材料

一、一句话定位
   〔这个人在同类人中是什么定位：最擅长什么 + 适合什么场景 + 当前在找什么〕

二、核心能力与证据
   · 能力 A —— 证据：（做了什么 + 量化结果 + 证据等级）
   · 能力 B —— 证据：…
   · 能力 C —— 证据：…
   〔按对目标岗位的相关度排序，不按时间顺序〕

三、对贵司岗位的直接价值
   〔针对这个具体岗位，说明他能立刻接手哪一块、哪一块需要过渡期。
     这一段是推荐材料里唯一不能从简历直接抄的部分——必须针对岗位写。〕

四、需要沟通确认的事项
   〔列出 1–3 条建议在面试中重点确认的点。
     写这一段的作用是：让用人主管感到这份材料是认真做的，
     同时把面试变成有方向的对话，而不是重复简历。〕

五、匹配度与待确认项
   · 已满足的要求：…
   · 部分满足（附在岗可迁移判断）：…
   · 尚无证据、需面谈确认：…
   〔用"已满足/部分满足/待确认"三态，不用分数、不用等级〕
```

### 写作要点

**把"他做过什么"改写成"他能做什么"**。客户不关心候选人上一家公司的内部流程，客户关心这个人到了自己这里能干什么。

**主动写出待确认项，反而提升可信度**。一份列出全部优点的推荐材料，会让经验丰富的用人主管怀疑；一份坦诚标注"这两项尚无证据，建议面谈确认"的材料，会被认为专业。

**不要在推荐材料里放薪酬区间**——除非客户明确要求。薪酬锚定是内部决策工具，放出去会过早暴露谈判空间。

## 四、从岗位族缺口反推机会

这一步常被忽略，但它是从"一个人"到"一个订单"的关键跳跃。

**逻辑**：如果某个职能族里，这个人只满足了部分条件，说明**这个岗位族存在结构性的人才缺口**——而缺口就是商机。

**输出格式**：
```
### 人才结构机会点
· 〔职能族〕：候选人可覆盖 〔已满足项〕；缺口在 〔缺失项〕
  → 缺口性质：能力项缺口（可通过降低要求或换人补）/ 经验项缺口（市场整体稀缺，需长期寻访）/ 结构项缺口（组织或编制问题，不该用招聘解决）
  → 建议动作：〔继续寻访同族 / 向客户提出编制或分工建议 / 暂不推进〕
```

**"结构项缺口"这一类尤其重要**：很多需求本质上是管理问题或编制问题，不是招聘问题。顾问在这一点上帮客户避免错误决策，比多推一个人更有价值。

## 五、常见推导错误

| 错误 | 表现 | 纠正 |
|---|---|---|
| 按现岗位推岗位 | 直接把人投回原岗位 | 抽能力原子后重挂族 |
| 一个族都不给 | 只说"他很优秀，能做很多事" | 推导不出来就是证据不足，写明缺什么 |
| 职级写死 | "可以投总监" | 写层级描述 + 区间 |
| 关键词堆砌 | 一次给 30 个词 | 每族 10–15 个，分五类写清 |
| 把缺口当减分项 | "他缺A所以不行" | 缺口 → 对应的动作（补证据/换方向/暂缓） |
| 无视市场 | 推导不考虑目标公司现招什么 | 市场确定性作为排序第三维，需外部数据支撑 |
